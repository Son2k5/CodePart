Four-layer solution rooted at `src/Api/CodePath.Api/Program.cs`:
- `CodePath.Api` — ASP.NET Core host wiring Kestrel, JWT Bearer (`HmacSha256`, token blacklist via Redis), CORS, ForwardedHeaders, global exception handling, correlation-id middleware, rate limiting policies, and endpoint maps per feature (`AdminEndpoints`, `AuthEndpoints`, `ExerciseEndpoints`, `JudgeEndpoints`, `TeacherEndpoints`, `ClassEndpoints`, `LearningEndpoints`, `AiEndpoints`).
- `CodePath.Application` — MediatR command/query handlers organized by feature folder (`Admin`, `Auth`, `Classes`, `Exercises`, `Teaching`, `Users`, `Ai`, `Judge`, `Learning`); each feature exposes `Abstractions/` interfaces that Infrastructure implements. Validation via FluentValidation behaviors; shared `Result<T>` pattern from Shared.Kernel.
- `CodePath.Domain` — POCO entities, enums, domain exceptions, and pure domain rules with no framework dependencies.
- `CodePath.Infrastructure` — concrete EF Core `AppDbContext` (Pomelo.MySql, split across `AppDbContext.{Students,Teachers,Teaching,Sessions,Learning,Rag,Classes}.cs`), per-feature DbContext abstractions, Redis-backed services (OTP, login attempts, password-reset limiter, token blacklist, health probe), BCrypt password hashing, SMTP email, Judge0 integration, Cloudinary storage, Python RAG client, and hosted workers (`RefreshTokenCleanupService`, `RagIndexWorker`, `JudgeWorker`).
- `CodePath.Shared.Kernel` / `CodePath.Shared.Web` — cross-cutting types: `Result<T>`, `DomainException`s, `BaseEntity`, `IDomainEvent`/`IIntegrationEvent`, global exception handler, Swagger extensions.
Dependency direction is strictly Api → Application → Domain, with Infrastructure depending on Application.Abstractions only. Feature toggles (`Judge:Enabled`, `Ai:Enabled`) gate optional subsystems in Program.cs.
